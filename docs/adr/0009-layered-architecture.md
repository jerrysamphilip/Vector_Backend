# ADR 0009: Layered architecture (route / service / domain / repository / adapter / UI)

Status: Accepted (2026-10). Refines [ADR 0001](0001-layering-and-domain-errors.md): services keep the
business rules and the domain errors, but SQL moves out of them into repositories. Plan and chunk list:
[../REFACTOR_PLAN.md](../REFACTOR_PLAN.md).

## Context

ADR 0001 split routers from services, but "services own all DB reads and writes" left SQLAlchemy queries
spread across about 66 service modules and 34 router modules (routers also import ORM models directly in
126 places). Business rules and SQL sit in the same functions, so a service cannot be unit-tested without
MySQL, and the same filter / sort / paging arguments are re-declared per endpoint. External systems (SES,
IMAP/SMTP, OpenAI, Microsoft 365) are called from services directly and replaced in tests by module
patching.

## Decision

Six layers, each with one job:

| Layer | Folder | May contain | May not |
|---|---|---|---|
| Route | `app/routers` | Parse the request, `Depends`, call **one** service function, map the result to a response model | SQLAlchemy, ORM models, repositories, business rules |
| Service | `app/services` | Business rules, record-level permissions, the transaction (unit of work); calls repositories and adapters through Protocols | SQLAlchemy queries, FastAPI types (`HTTPException`, `UploadFile`, `Request`, ...) |
| Domain / query | `app/domain` | Typed query / filter / paging objects (parameter objects), value objects, shared enums, pure rules | Any I/O; SQLAlchemy, FastAPI, models, services, repositories, routers (also indirectly, so not `app.core.errors`) |
| Repository | `app/repositories` | All SQL and ORM mapping, one module per aggregate, every call tenant-scoped | Business rules, commits, FastAPI, services, routers |
| Adapter | `app/adapters` | SES/SNS, IMAP/SMTP, OpenAI, storage, Microsoft 365 behind `typing.Protocol`s, plus their providers | Business rules, services, routers |
| UI | frontend `src/api` + react-query; Tailwind 4 + Radix UI primitives | Calls routes only, through one read hook and mutations | Hand-rolled fetch in effects, hand-rolled accessible widgets |

`app/core` (config, engine, auth, errors) and `app/schemas` keep their ADR 0001 roles. Building blocks:
`app/domain/paging.py` (`Paging`, `Sort`, `Page[T]`) and `app/repositories/base.py` (`Repository` and
`UnitOfWork` Protocols, `SqlAlchemyRepository`, `SqlAlchemyUnitOfWork`).

**Transactions.** The service owns the unit of work: one service call is one transaction.

```python
def rename_contact(uow: ContactsUnitOfWork, tenant_id: str, contact_id: UUID, name: str) -> Contact:
    with uow:
        contact = uow.contacts.get(tenant_id, contact_id)
        if contact is None:
            raise NotFoundError("Contact not found")
        contact.name = name          # rules live here
        uow.commit()
        return contact
```

Repositories stage changes in the unit of work's session and never commit. An exception inside the
`with` block rolls back; uncommitted work is discarded when the session closes. In a request the unit of
work borrows the `get_db` session (`SqlAlchemyUnitOfWork.for_session(db)`); the worker and scripts give it
`SessionLocal`. Routers stop calling `db.commit()` as their aggregate migrates.

**Unit tests per layer** (tests/unit, no database, see [0006](0006-test-framework-layers.md)):

- route: the router with a fake service (`app.dependency_overrides`), asserting status, body and the
  arguments passed down;
- service: fake repositories (in-memory dicts implementing the Protocol) and fake adapters;
- domain: plain tests of pure functions and value objects.

Repositories and query objects are tested against MySQL in the functional layer (tests/*.py), including
tenant isolation per table.

**Enforcement.** `.importlinter` encodes the table (contracts `routers-thin`, `services-no-sql`,
`domain-pure`, `repositories-no-upper`, `adapters-no-upper`). Today's violations are listed exactly in
the "BASELINE 2026-10 (shrink only; see REFACTOR_PLAN.md)" blocks, generated by
`scripts/ci/gen_import_baseline.py`; a stale entry fails `lint-imports`, so the lists only shrink.
Import-linter sees external packages only by their top-level name: routers are forbidden all of
`sqlalchemy`, including `sqlalchemy.orm.Session` for `Depends` typing. Migrated routers type the session
through an alias exported by `app.core.database` instead. Rules that are not imports (a router calls only
one service function; no business rules in repositories) are review items.

## Migration

Aggregate by aggregate, never a big-bang rewrite. Chunk L1 moves the contacts aggregate as the reference
(typed `Mapped[]` models, `app/domain/contacts.py`, `app/repositories/contacts.py`, thin routers, unit
tests per layer); chunks A1-A8 follow the same pattern on disjoint files and S2 moves external clients
into `app/adapters`. Each chunk deletes its aggregate's baseline entries (and its C-1 / C-5 baseline
entries) in the same change; new code is written in the target shape from now on.

## Consequences

- Services become testable without MySQL; the functional layer concentrates on SQL and tenancy.
- More files per feature (domain object, repository, Protocol); accepted for the isolation it buys.
- Until an aggregate migrates, its routers and services keep the ADR 0001 shape, visible in the baseline.
- ORM objects may still cross the service boundary to the router's response mapping; response models
  (C-8) keep that mapping explicit.
