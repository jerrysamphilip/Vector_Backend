# CI gates (NTS Build Standard Addendum)

Every gate below is **blocking** in CI. Where the code base could not pass a rule on the day the gate was
introduced (2026-10-18), the gate enforces a checked-in, dated **baseline** instead of a lower threshold.

## Ratchet policy

- A baseline lists today's violations, nothing more. The rule's threshold is never lowered globally.
- Baselines **only shrink**. Each gate fails on a *new* violation, on a baselined item getting *worse*, and on a
  baseline entry that no longer matches the code (stale entries must be deleted in the same change that fixes
  them, so the slot cannot be reused by a later regression).
- Regenerating a baseline (`--update`) refuses to add new or worse entries. Adding one anyway is an exception:
  it needs a reviewer's approval in the pull request and a reason next to the entry (or a TODO in
  `.importlinter`).
- Ignore lists for dependency audits carry an id, the date added, a review-by date and a reason; an entry past
  its review date fails the gate.

Run them all locally from the repo root:

```bash
pip install -r requirements.txt -r requirements-dev.txt
ruff check . && mypy && bandit -q -r app -t B101 && lint-imports
python scripts/ci/check_complexity.py && python scripts/ci/check_type_ignores.py
python scripts/ci/check_local_imports.py && python scripts/ci/check_version.py
python scripts/test.py trace --check && python scripts/ci/run_pip_audit.py
python -m pytest -q tests/unit --cov=app --cov-report=json:reports/coverage-unit/coverage.json
python scripts/ci/check_coverage.py --layer unit --report reports/coverage-unit/coverage.json
```

After shrinking a baseline: `python scripts/ci/check_complexity.py --update`,
`python scripts/ci/check_type_ignores.py --update`, `python scripts/ci/check_local_imports.py --update`,
`python scripts/ci/check_coverage.py --layer <layer> --report <coverage.json> --update` (raises floors), or
delete the line from `.importlinter` / an ignore list by hand. For the ADR 0009 blocks,
`python scripts/ci/gen_import_baseline.py` reports new and stale entries and `--update` rewrites the
blocks (it refuses to add entries; `--allow-new` needs a reviewer's approval). Every `lint-imports`
contract fails on an ignore that no longer matches an import (`unmatched_ignore_imports_alerting` is
left at its default, `error`).

## Coverage

Introduced 2026-10-25 (refactor plan chunk Q0). Coverage of `app/` is measured per test layer, separately,
with branch coverage on (`.coveragerc`):

- **unit** (job `unit`, `scripts/test.py run unit --extra="--cov=app ..."`): how much logic is tested without a
  database. This is the number the layering refactor is meant to raise.
- **functional** (job `test`, `pytest tests --ignore=tests/unit --cov=app ...`): the total the in-process API
  tests reach against MySQL.

`scripts/ci/check_coverage.py --layer <layer> --report <coverage.json|coverage.xml>` computes line % and
branch % for `app` as a whole and for each package listed under `packages` in `ci/coverage_floor.json`
(`app.routers`, `app.services`, `app.core`, `app.utils`, `app.domain`, `app.repositories`; a package is
measured only when the report has statements for it) and compares them with that layer's floors:

- a value more than its layer's tolerance below its floor **fails**: `tolerance_pp_by_layer` (unit 0.1 pp; functional 0.5 pp, because threaded / timing-dependent paths move per-package figures by a few tenths between identical runs), else `tolerance_pp`;
- a floor whose package is no longer in the report **fails** (renamed or removed: lower it explicitly);
- a package without a floor (`NEW`) or a value 1 pp or more above its floor (`ABOVE`) is reported only.

Reports are uploaded as the artifacts `coverage-unit` and `coverage-functional` (JSON, Cobertura XML, HTML),
and the per-package table is written to the job summary.

Ratchet: floors only go up. `--update` raises the layer's floors to the current values (rounded down to
0.01) and adds floors for new packages; it never lowers one and refuses when a value is below its floor.
Lowering needs `--update --allow-lower "REASON"`, which writes the date, layer, package, metric, old and new
floor and the reason to `lowered` in the floors file, and a reviewer's approval in the pull request (as for
any baseline exception above). Raise the floors in the same change that adds tests.

## Requirement status (docs/REQUIREMENTS.md)

`Fixed` and `Decision` and `Change request` are in scope and need a test case; `Out of release` does not.
Moving a requirement out of the release needs product-owner sign-off, recorded in its Notes column and in
CHANGELOG.md. Requirements referenced by a case but missing from the register fail the gate.
